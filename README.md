# doc-provenance

Подтверждение подлинности документов и неизменности журналов: свой удостоверяющий центр,
электронная подпись в формате CMS и дерево хэшей с подписанной вершиной.

Задача, из которой вырос проект. Сайт выдаёт документы с числами — таблицы и отчёты.
Получивший такой файл от третьего лица не может узнать, тот ли это документ, что выдал сайт,
или в нём поправили число. Библиотека закрывает оба конца цепочки:

- **документ** получает отсоединённую подпись (`.p7s`); проверить её может любой, у кого есть
  корневой сертификат, — этой библиотекой или OpenSSL;
- **исходные файлы**, из которых сайт берёт числа, записаны в журнал; его вершина подписана,
  и подмену файла вместе с записью о нём проверка замечает.

Работа выполнена по дисциплине «Криптографические методы защиты информации»; постановка —
в [docs/ЗАДАНИЕ.md](docs/ЗАДАНИЕ.md). Библиотека встроена в веб-приложение RegionLens:
там она подписывает выгружаемые документы и архив выпусков статистики.

## Что внутри

| Модуль | Что делает | Стандарт |
|---|---|---|
| `provenance.ca` | корневой сертификат, сертификат подписи документов, список отзыва | X.509, RFC 5280, RFC 9336 |
| `provenance.cms` | подпись документа и её проверка | CMS, RFC 5652 |
| `provenance.der` | строгий разбор DER для проверки подписи | X.690 |
| `provenance.merkle` | дерево хэшей, доказательства включения и согласованности | RFC 6962 |
| `provenance.log` | журнал с подписанной вершиной и историей вершин | — |
| `provenance.cli` | команда `provenance` | — |

Алгоритмы: ECDSA на кривой P-256, SHA-256. Зависимость одна — `cryptography`.

## Показ за минуту

```bash
python demo/run_demo.py
```

Сценарий создаёт центр, подписывает документ и проводит пять атак: изменённое число, чужой
центр с теми же именами, украденный ключ, подмена файла в архиве вместе с описью, откат
журнала. По каждой печатает, принята проверка или отклонена и почему. Файлы остаются
в `demo/out`.

## Работа из командной строки

Центр и сертификат службы. Корневой ключ нужен только для выпуска сертификатов и списков
отзыва; пароль к нему берётся из переменной `PROVENANCE_PASSPHRASE`.

```bash
provenance ca init ca --name "Корневой центр" --org "Организация"
```

```bash
provenance ca issue ca --name "Служба подписи" --org "Организация" --out service
```

Подпись и проверка. Рядом с файлом появляется `report.csv.p7s`.

```bash
provenance sign report.csv --key service/signer.key --cert service/signer.crt
```

```bash
provenance verify report.csv --root ca/root.crt --crl ca/crl.pem
```

Отзыв сертификата — после него проверка отклоняет все его подписи:

```bash
provenance ca revoke ca service/signer.crt
```

Журнал: подписать, проверить, выдать доказательство для одной записи.

```bash
provenance log seal MANIFEST.csv --key service/signer.key --cert service/signer.crt
```

```bash
provenance log verify MANIFEST.csv --root ca/root.crt --crl ca/crl.pem
```

```bash
provenance log prove MANIFEST.csv 3 --out proof.json
```

```bash
provenance log check-proof proof.json --head MANIFEST.csv.head.json
```

Та же проверка подписи без этой библиотеки:

```bash
openssl cms -verify -binary -inform DER -in report.csv.p7s -content report.csv -CAfile ca/root.crt -purpose any -out /dev/null
```

## Как проверяется подпись

1. **Документ тот самый.** SHA-256 файла сравнивается с хэшем, записанным в подписанных
   атрибутах подписи.
2. **Атрибуты подписал владелец сертификата.** Подпись ECDSA проверяется открытым ключом
   из сертификата, вложенного в подпись.
3. **Сертификату можно верить.** Он выпущен корневым центром, который проверяющий получил
   заранее и не из подписи; предназначен для подписи документов; действовал в момент
   подписи; не отозван.

Отказ на любом шаге называет причину кодом: `document_changed`, `bad_signature`,
`untrusted`, `wrong_purpose`, `not_valid_then`, `from_future`, `revoked`, `bad_crl`,
`unsupported`, `malformed`.

## Как устроен журнал

Запись журнала — строка: например, хэш файла, его размер и происхождение. Над записями
строится дерево хэшей; вершина дерева с числом записей и временем подписывается.

- Изменить, убрать или переставить запись, не изменив вершину, нельзя.
- Пересчитать вершину после подмены можно, подписать — нет.
- Откат к прежнему журналу с его же настоящей подписью выдаёт история вершин: новый журнал
  обязан продолжать каждую прежнюю вершину.
- Одна запись доказывается коротким путём — около log2(n) хэшей — без остального журнала.

## Принятые ограничения

- **Один набор алгоритмов.** Подпись другого вида отклоняется, а не проверяется как
  получится. Поля подписи, которые сама подпись не защищает, принимаются в одном виде —
  поэтому любой изменённый байт подписи ведёт к отказу; это проверяет тест.
- **Цепочка в два звена:** корневой сертификат выпускает сертификат подписи напрямую.
- **Время подписи пишет подписавший.** Доверенной метки времени нет, поэтому отозванному
  сертификату не верят и за прошлое: укравший ключ поставил бы любое время.
- **История вершин лежит рядом с журналом.** От отката она защищает, пока её копия есть
  вне сервера — в резервной копии или в публикации.
- Алгоритмы ГОСТ не используются. Библиотека с открытым кодом не является средством
  криптографической защиты, прошедшим оценку соответствия.

## Проверки

```bash
uv run pytest
```

- вершины и путь дерева сверены с контрольными значениями эталонной реализации
  Certificate Transparency;
- доказательства проверены полным перебором для деревьев до 33 записей;
- подпись проверена в обе стороны с OpenSSL: он принимает подпись библиотеки и отклоняет
  те же подделки, а библиотека принимает подпись, сделанную OpenSSL;
- порча каждого байта подписи по очереди ведёт к отказу.
